# Ariadne v0.3.0 — Deterministic Scope Topology

Published 2026-07-16: [GitHub Release](https://github.com/pariyar07/ariadne/releases/tag/v0.3.0)

`v0.3.0` makes nested scopes explicit, stable, and recoverable. Canonical Markdown checkpoints now define scope identity and ancestry, while deterministic generated maps give agents and people a consistent view of the vault without making Obsidian a requirement.

## Highlights

- Every adopted scope has a schema-v1 descriptor with an immutable `scope_id`, canonical vault-relative path, nearest adopted parent, lifecycle status, and deterministic sibling order.
- Four marker-managed Markdown checkpoints provide the boundary, inheritance chain, navigation, and task routing surfaces needed for cold-start operation.
- `Bases/Scope Registry.base`, the generated tree in `Agent/Scope Map.md`, and `Agent/Scope Map.canvas` are derived from canonical descriptors. Bases and Canvas remain optional view layers.
- `--profile scope` supports deterministic whole-vault or subtree validation. Stable findings roll up into `scope-adoption-warnings`, `scope-contract-warnings`, and `scope-map-warnings`.
- The dependency-free synchronizer previews exact writes, requires a declarative authorized path set, verifies preconditions, serializes writers, and records resumable operation manifests.

## Existing Vaults

The new contract is opt-in. Updating installed skills does not modify vault content or activate strict topology.

Choose either whole-vault adoption or a root-to-target ancestor-chain adoption. Both preserve legacy notes, named hubs, and user content outside managed blocks. Adoption does not implicitly move, merge, rename, archive, or delete content. See [Scope Topology Migration](../guides/scope-topology-migration.md) before writing.

Preview and validate with the installed scripts:

```bash
node /path/to/skills/validator/scripts/sync_scope_topology.js "/path/to/vault" --check
node /path/to/skills/validator/scripts/validate_vault.js "/path/to/vault" --profile scope
node /path/to/skills/validator/scripts/validate_vault.js "/path/to/vault" --scope "Domains/Product" --profile scope
```

After an authorized topology write, run scoped validation, whole-vault validation, and a second synchronizer check that proposes no changes. Interrupted operations require explicit `--resume <operation-id>` or `--abort <operation-id>` handling; abort reports reconciliation paths and is not a content rollback.

## Migration Boundaries

- Stable IDs, lifecycle changes, relocation, reparenting, and cleanup remain explicit decisions.
- User Base formulas are report-only and are never silently authorized or rewritten.
- Root activation is written last during adoption, so strict topology cannot claim a partially adopted tree.
- Unsupported root schema versions disable topology claims and produce warnings instead of mutation.
