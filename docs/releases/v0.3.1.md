# Ariadne v0.3.1 — Scope Topology Adoption Fixes

`v0.3.1` is a non-breaking patch release that fixes defects in v0.3.0's legacy scope adoption path, generated YAML serialization, and topology ordering. No schema change, no new skills, no vault migration beyond what v0.3.0 already documented.

## Fixed

- `adopt` can now discover legacy candidates from local `AGENTS.md` presence, so whole-vault and ancestor-chain adoption work on a vault with zero pre-existing `type: scope-index` descriptors. Previously a genuinely unmigrated vault (root included) could never take its first `sync_scope_topology.js --write` step.
- Generated frontmatter (`title`, `scope_path`, `former_scope_paths`, and move's redirect fields) is now serialized through a minimal YAML scalar quoter that quotes every generated string scalar unconditionally, so values a real YAML parser would otherwise misinterpret (implicit types, leading indicators, control characters including the full Unicode `Cc` category, values needing both quote styles) are either quoted correctly or refused with a clear error.
- A folder whose physical path can't safely become a `scope_path` -- illegal characters, a lossy backslash-to-slash normalization, or an on-disk spelling that isn't already Unicode-NFC-normalized -- is refused at discovery instead of silently adopted.
- `adopt`'s write-time model now merges newly-selected candidates into the existing active topology instead of replacing it, fixing incremental adoption against an already-active root.
- `Agent/Scope Map.canvas` nodes are now individually readable: each scope's file node is paired with a generated text label carrying its title, `scope_id`, and `scope_path`, instead of every node showing the same "00 Index" filename.
- A directory ancestor-resolution sort bug that could silently drop a whole subtree from the topology (when a folder name sorted ahead of root in file-scan order) is fixed; root now always sorts at depth 0.
- `adopt` no longer reinterprets a directory with a malformed *explicit* `type: scope-index` descriptor as ordinary legacy content, honors `ariadne_scope_adoption: dismissed` on any named legacy index (not only `AGENTS.md`/bare `00 Index.md`), and never treats hidden/tool-owned directories (`.ariadne`, `.claude`, `.codex`, etc.) as legacy candidates.
- A full-path scope_id collision (e.g. `A-B/X` and `A/B/X` both slugifying to `a-b-x`) is now disambiguated with a deterministic hash suffix instead of refusing.

See the [changelog](../../CHANGELOG.md) for full technical detail on each fix.
